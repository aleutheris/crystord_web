# ADR-260065: Compute Authoring and Transparency — Formula Builder, Status Badges, and Emphasis Wiring

Status: Accepted
Date: 2026-07-18
Owners: Crystord App maintainers (info@aleutheris.com)

> Approval note: accepted under the project owner's batch delegation of 2026-07-17 covering
> the UI-exposure program's plan/decision approvals (recorded in `epic-index.md`).

## Context

The backend `operation` engine (SUM/MINUS/PRODUCT/DIVIDE/COLLECT, typing, dependency graph,
evaluation reporting) exists and is the product's headline differentiator (Q3), but the UI
cannot even edit the field. Schema facts that shape this decision: the canonical payload is
function-style JSON serialized as a string (`{"name":"SUM","args":[...]}`; args are atom UUIDs
or constant keys); `discoverOperations` returns **name + description only — no arity or type
metadata**; evaluation state rides on `AtomOutput` as untyped fields (`evaluationStatus`,
`errorCode`, `causes`, `cycleNodes`, `cycleEdges`, `originNodeUuid`, `affectedNodeUuid`);
there is **no dedicated result field** — the computed value rides in `content`; and
`OP_DEPENDENCY` bonds are system-managed (already stripped by `updateAtom`). EPIC-260066
reserved the `AtomNodeData.computeStatus` badges region and shipped the preferences contract
whose documented semantics this epic consumes: `homeEmphasis` `compute` → Flow is the
prominent landing; `computeBadges` `always`/`onDemand`.

## Decision

1. **Formula builder in a Compute inspector tab** (feature `workspace-compute`, registered
   `compute` after Classify). Function picker lists `discoverOperations`; a client-side
   metadata table supplies arity for the built-ins — SUM (1+), MINUS (exactly 2), PRODUCT
   (2+), DIVIDE (exactly 2), COLLECT (special) — with a generic variadic args editor for
   unknown names. Users never see or type the JSON payload.
2. **Payload helpers in api-contract.** Pure `operation-payload.ts` parses/serializes the
   canonical payload (tolerant parse: malformed/legacy strings degrade to a raw-string
   view, never a crash); `compute-operations.ts` holds `DISCOVER_OPERATIONS_QUERY`;
   `compute-status.ts` folds the evaluation fields into a small badge model
   (`ok | error | skipped`, computed-only) consumable by both the tab and the graph feature.
3. **Argument slots.** Each arg is an atom reference or a constant key. The atom-reference
   picker searches the current working set by title (never raw UUID entry) — enabled by an
   **additive** `InspectorTabProps.atoms?: Atom[]` (the Inspector passes
   `workingSet.atoms`); existing UUID args render resolved titles with a shortened-UUID
   fallback for out-of-set references. Constants edit as a key/value list; COLLECT's single
   arg is the registered query name (known registry: `atoms_with_labels`, free-text
   fallback) with its `labels` constant edited via the shared `LabelChipEditor` — label-only
   until the backend adds category collect.
4. **Manual-vs-computed hard fork.** A non-empty `operation` makes Details/Table content
   read-only (already shipped); the Compute tab owns the operation and offers
   "Convert to manual" (two-step confirm) which clears `operation` (+ `constants`) and
   re-enables content.
5. **"Explain this value."** A section in the tab renders the evaluation state in plain
   language (calm competence): success → "Up to date"; failed-origin → cause via `errorCode`
   (division by zero, missing dependency, type mismatch); failed-propagated → the failing
   inputs by title (`causes` resolved against the working set); cycle → the loop's members;
   skipped-optional → "an optional input is absent."
6. **Flow visualization.** `RETRIEVE_QUERY` gains the evaluation fields (optional on `Atom`,
   mock-compat). GraphCanvas stamps `computeStatus` into the reserved badges region; cycle
   members get error badges and cycle edges danger styling. Flow-only (the seam exists on
   `AtomNode` only — Network untouched).
7. **Emphasis wiring (Q3, per the T4 documented semantics).** `computeBadges`: `always` →
   badges on every computed atom; `onDemand` → only the selected atom (`ViewProps` gains
   optional `computeBadges?: 'always' | 'onDemand'`, passed by the shell). `homeEmphasis`
   drives the **initial active view**: `compute` → Flow, `relationship` → Network (falling
   back to the first enabled view); the affected architecture assertion and the
   Network-default E2E scenarios are updated in the same task (relationship emphasis primed
   via localStorage where a Network-default scenario is kept).
8. **No charts.** Confirmed: v1 transparency is badges/graph/table only (REQ-CR-260010);
   any future charting requires its own ICR.

## Alternatives Considered

- **Typed operation signatures from the backend:** not available (`OperationFunction` is
  name+description only); a client-side metadata table is the honest interim, with the
  generic editor keeping unknown operations usable rather than blocked.
- **A free-form JSON editor for `operation`:** rejected — the epic exists to kill JSON
  typing; the payload helpers make the string an implementation detail.
- **Charting library for computation transparency:** rejected by REQ-CR-260010; badges +
  Flow + "Explain this value" realize Q3 with the current stack.
- **Applying badges to the Network view too:** rejected — the region seam exists on the Flow
  `AtomNode` only; porting it without a designed circle treatment is EPIC-260072's call.

## Consequences

- Positive: the differentiator becomes usable end-to-end (author → status → explanation →
  dependency rendering); the emphasis preferences finally have a consumer; payload/status
  logic is pure and fully testable in api-contract.
- Negative: a client-side arity table can drift from the backend registry (mitigated by the
  generic fallback editor); the default landing view flips to Flow for compute emphasis,
  which reshapes two long-standing E2E scenarios.
- Risks: evaluation fields are untyped strings — the status mapper treats unknown values as
  no-badge rather than guessing.

## Verification

- Unit: payload parse/serialize round-trips + malformed tolerance; arity enforcement per
  built-in; picker resolution incl. out-of-set fallback; status mapper for every documented
  evaluationStatus/errorCode combination; Explain copy per state; convert-to-manual payload.
- E2E: build a SUM over two atoms without typing JSON (change payload asserted); computed
  atom shows badge + explanation; cycle styling; emphasis default-view scenarios.
- Architecture: `workspace-compute` module/barrel/registry; ViewProps/InspectorTabProps
  additive extensions; initial-view derivation from `homeEmphasis`.

## Rollback

The tab and badges register/stamp additively: removing the descriptor, the badge stamping,
and the initial-view derivation restores the prior behavior. The evaluation-field selection
is additive and harmless to keep.
