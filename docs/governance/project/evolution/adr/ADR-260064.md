# ADR-260064: Categories Navigator — Lazy Browse Tree, Facet Scoping, and Inline Taxonomy Authoring

Status: Accepted
Date: 2026-07-17
Owners: Crystord App maintainers (info@aleutheris.com)

> Approval note: accepted under the project owner's batch delegation of 2026-07-17 covering
> the UI-exposure program's plan/decision approvals (recorded in `epic-index.md`).

## Context

The brand promise is "the user can see what data exists," yet the schema-9.2.0 hierarchical
category model (dimensions → values) has no browse surface: categories can be neither browsed
nor used as filters, and a hierarchy cannot live in a text box. EPIC-260066 shipped the
navigator registry and the shared permission-aware `CategoryTree`; EPIC-260067 (ADR-260063)
introduced the `category-operations.ts` api-contract module and the `Dimension ▸ Value` chip
grammar this navigator reuses. **The taxonomy permission model is live schema data** —
`Category*Output` carries a real per-node `accessLevel` — so edit gating needs no speculative
seam (Q2: no admin-only management surface).

## Decision

1. **Lazy browse tree.** `CategoriesNavigator` (new feature `workspace-categories`) renders
   the shared `CategoryTree`: top level = dimensions via `retrieveCategoryDimensions`; values
   lazy-load on expand via `retrieveCategoryBrowse(dimensionKey)` for roots and
   `retrieveCategoryBrowse(valueKey)` for subtrees; count badges come from
   `CategoryChildCount.atomCount`. Atoms under a node are **not** listed in the rail —
   navigators scope, views represent (count badges only).
2. **Facet scoping contract.** Facet state (`CategoryFacetFilter[]`, the ui-primitives
   `WorkspaceFilter` shape) is owned by `WorkspaceShell`. `NavigatorProps` extends
   **additively** with `filter?: WorkspaceFilter` and `onFilterChange?: (f: WorkspaceFilter)
   => void` — the contract EPIC-260066 deferred here. Value selection toggles that value in
   its dimension's facet entry: OR within a dimension, AND across dimensions; one rail-level
   "Include subcategories" checkbox (default on) sets `includeDescendants` for new entries.
3. **Chips + immediate re-fetch.** Facet chips render in the shell header next to the
   SearchBar (removable, `Dimension ▸ Value` grammar from EPIC-260067); the shell appends the
   facet summary to the `QuerySummary` string. Facet changes trigger an immediate re-fetch
   combining the current submitted labels + facets: `GraphData.search` gains an optional
   `categories?` argument and `RETRIEVE_QUERY` a `$categories: [CategoryFilterInput!]`
   variable.
4. **Inline taxonomy authoring.** Rail header ＋ adds a dimension; per-node affordances (via
   `CategoryTree`'s `canEditNode`/`onEditNode` + an inline editor): rename
   (`updateCategoryDimension`/`updateCategoryValue` displayName), add child value
   (`createCategoryValue`), delete (guarded — backend `CAT-*` errors surfaced verbatim
   through the mapper's generic path). No admin surface (Q2).
5. **Real permission gating.** `canEditNode` = the node's real `accessLevel` ∈ {OWNER,
   EDITOR} from `Category*Output.accessLevel` — gating is live data, not a seam. Taxonomy
   share/transfer UI is out of scope (mirrors EPIC-260074's model in a future epic).
6. **Lens switcher.** This adds the second navigator, so the left rail gains the
   registry-driven lens switcher (Labels | Categories) mirroring the GraphViewTabs ARIA tab
   pattern.

## Alternatives Considered

- **Drag-to-reparent values:** deferred — the connect/disconnect operations exist, but drag
  UX is disproportionate here; recorded as a follow-up, not a task.
- **An admin-only taxonomy management surface:** rejected by Q2 — authoring is inline in the
  rail, gated per node on real access levels.
- **Listing atoms under tree nodes in the rail:** rejected — navigators scope, views
  represent; the rail carries count badges only.
- **A taxonomy sharing/transfer UI:** out of scope — grants exist in the schema, but
  surfacing them is a future epic mirroring EPIC-260074's model.

## Consequences

- Positive: makes the category model browsable and usable as working-set scope; delivers the
  deferred `NavigatorProps` filter contract additively; inline authoring without a new admin
  surface; the second navigator brings the lens switcher into existence.
- Negative: the shell takes on facet state and a wider query summary; the rail gains
  authoring affordances that must stay gated per node.
- Risks: facet semantics (OR/AND/`includeDescendants`) are easy to get subtly wrong — covered
  by dedicated unit tests; delete is guarded by backend `CAT-*` errors surfaced verbatim.

## Verification

- Unit: facet selection semantics (OR within a dimension, AND across dimensions,
  `includeDescendants`); lazy-load expansion + count badges; `canEditNode` gating on the real
  node `accessLevel`.
- E2E: browse the tree, filter the working set via facets, author taxonomy inline (add,
  rename, delete).
- Architecture: `workspace-categories` in FEATURE_MODULES/barrels; navigator registered; lens
  switcher present.

## Rollback

The navigator registers additively; removing its descriptor + feature dir restores the
Labels-only rail. The `NavigatorProps` filter fields and the `RETRIEVE_QUERY` categories
variable are optional additions and harmless to keep.
