# ADR-260069: Atom Sharing Surface — Owner-Only Grants Management

Status: Accepted
Date: 2026-07-18
Owners: Crystord App maintainers (info@aleutheris.com)

> Approval note: accepted under the project owner's batch delegation of 2026-07-17 covering
> the UI-exposure program's plan/decision approvals (recorded in `epic-index.md`).

## Context

The backend supports atom-level sharing — a branding pillar ("Control") — invisible in the
UI. Read-side gating already exists (BI-260061 / ADR-260059). Schema facts:
`listAtomGrants(atomUuid): [AtomGrantOutput!]!` (**owner-only**) returns `principalUuid,
principalType, principalName, level, grantedAt, grantedBy`; `shareAtom(atomUuid, principal,
principalType, level)` and `revokeAtomAccess(atomUuid, principal, principalType)` are
owner-only; principals are **usernames** (USER) or **workspace keys** (WORKSPACE) resolved
by the backend (`CR-16-PRINCIPAL-UNKNOWN` is already in the central mapper); the grantable
`AccessLevel` is `EDITOR | VIEWER` — deliberately distinct from the caller-held
`EffectiveAccessLevel` which adds OWNER. `transferAtomOwnership` exists but is out of scope.

## Decision

1. **An owner-only Share inspector tab** (feature `workspace-share`, registered `share`
   after History) with `when: (atom) => atom.accessLevel === 'OWNER'` — every listed
   operation is owner-only server-side, so non-owners never see a tab that can only error.
   The tab states the atom's effective level for orientation.
2. **Grants list + grant/revoke flows.** The list renders principalName · principalType ·
   level · grantedAt with a per-row revoke behind an inline two-step confirm. The grant
   form: principal text input (username or workspace key), principal-type select, level
   select (EDITOR/VIEWER). Mutations refetch the grants list; feedback follows the
   established pending/feedback pattern via the central error mapper (raw message for
   unrecognized codes).
3. **Reuse-ready presentational split (Q2).** The grant list/form render as presentational
   components (grants + callbacks in, no atom coupling in the rendering layer) inside the
   feature, so a future taxonomy-sharing epic can lift them; they are **not** promoted to
   ui-primitives now (single consumer — the same rule that kept the atom-ref picker in
   EPIC-260069).
4. **Ownership transfer deferred.** `transferAtomOwnership` is a destructive single-owner
   handoff deserving its own confirmation UX slice — recorded, not built.
5. **Module shape.** New api-contract `sharing-operations.ts`: LIST_ATOM_GRANTS_QUERY,
   SHARE_ATOM_MUTATION, REVOKE_ATOM_ACCESS_MUTATION, `AtomGrant` type, grantable
   `AccessLevel` type; barrel-exported.

## Alternatives Considered

- **Showing the Share tab to non-owners (read-only):** rejected — `listAtomGrants` itself
  is owner-only; the tab would render only errors. The `when` predicate is the honest gate.
- **Ownership transfer in this slice:** deferred — destructive handoff needs its own UX and
  review; grants view/grant/revoke is the complete core loop.
- **Promoting the grant UI to ui-primitives now:** rejected — single consumer; the
  presentational split inside the feature preserves the future lift without speculative API.

## Consequences

- Positive: the Control pillar becomes actionable; grants become visible/revocable; the
  presentational split pre-pays the Q2 taxonomy-sharing reuse.
- Negative: an owner-only tab means the sharing surface is invisible to grantees (they see
  their level in the Share-less inspector; acceptable — they cannot act on grants anyway).
- Risks: principal typos surface as `CR-16-PRINCIPAL-UNKNOWN` — mapped to a clear message
  already.

## Verification

- Unit: grants list rendering; grant flow payload (principal/type/level); revoke two-step;
  refetch-after-mutation; error mapping incl. CR-16; `when` predicate (OWNER only);
  effective-level display.
- E2E: share an atom with a mocked principal and see the grant listed; revoke it; non-owner
  atom shows no Share tab.
- Architecture: `workspace-share` module/barrel/registry with a `when` gate; api-contract
  barrel exports the sharing documents.

## Rollback

The tab registers additively; removing the descriptor + feature dir + api-contract module
reverts the surface.
