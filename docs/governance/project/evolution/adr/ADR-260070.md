# ADR-260070: Board View — Root-Value Columns with Drag and Accessible Recategorization

Status: Accepted
Date: 2026-07-18
Owners: Crystord App maintainers (info@aleutheris.com)

> Approval note: accepted under the project owner's batch delegation of 2026-07-17 covering
> the UI-exposure program's plan/decision approvals (recorded in `epic-index.md`).

## Context

Reclassifying many atoms one inspector visit at a time is slow. The board (columns = one
dimension's values, cards = atoms, drag to recategorize) is the designed bulk-classify
surface, registering as a center **view** (it represents the working set) rather than an
inspector tab. Prerequisites are in place: the view registry (ADR-260061), the categories
round-trip on `updateAtom` (ADR-260063, replace-all semantics), and taxonomy reads in
`category-operations.ts` (ADR-260063/064). It ships in this round by the owner's direction
while remaining last in priority order — the most deferrable leaf.

## Decision

1. **A Board center view** (feature `workspace-board`, registered `board` after `table`)
   consuming the fixed `ViewProps` via a local structural props slice.
2. **Dimension picker → root-value columns + rollup.** A toolbar select over
   `retrieveCategoryDimensions` chooses the board's dimension (view-local state; a prompt
   state before choice). Columns = the dimension's **root values** (empty
   `parentValueKeys`) plus a leading **Unassigned** column. Membership: an atom lands in a
   root column when its assignment in this dimension is that root **or any descendant of
   it** — rollup computed client-side from the dimension's full value list (fetched once
   per chosen dimension); no assignment in this dimension → Unassigned. An atom with
   multiple assignments in the dimension appears in each matching column (a fact of the
   data model, rendered honestly).
3. **Recategorize = replace one dimension's entry.** Dropping a card on a value column
   assigns that **root** `valueKey`; dropping on Unassigned clears this dimension's
   assignments; assignments in **other** dimensions are preserved (rebuild the categories
   array, replace only this dimension's entries) through the shared `updateAtom`
   round-trip.
4. **Native HTML5 drag-and-drop, plus an accessible move menu.** No dnd library
   (REQ-CR-260010 lean). Every movable card also carries a "Move to…" menu (column select)
   — the keyboard/screen-reader path and the deterministic E2E path; drag alone would fail
   the accessibility floor. VIEWER atoms render non-draggable with no move affordance
   (`atomPermissions.canEdit`).
5. **Shared selection.** Card click selects the atom (inspector opens); the selected card
   reflects `selectedAtomId`. Cards show title + labels line.

## Alternatives Considered

- **All dimension values as columns (not roots-only):** rejected — deep taxonomies produce
  unbounded column counts; roots + rollup keeps the board scannable, and precise placement
  remains the Classify tab's job.
- **A drag-and-drop library:** rejected — REQ-CR-260010 lean; native DnD + the move menu
  covers the interaction honestly.
- **Folding the board into the Classify tab:** rejected — bulk classification is a
  working-set representation (center view), not a selection editor.
- **Persisting the chosen dimension in preferences:** deferred — view-local state for MVP;
  a preferences key is additive later if wanted.

## Consequences

- Positive: bulk reclassification becomes one gesture per atom; the fifth verb surface
  completes the program's center-view set (Flow · Network · Table · Board).
- Negative: rollup places atoms under root columns even when assigned to deep descendants —
  dropping such a card on its own root column coarsens the assignment to the root
  (documented on the move menu via the column's full meaning; precise assignment stays in
  Classify).
- Risks: native DnD is browser-quirky — the move menu is the guaranteed path and the E2E
  contract; drag handlers stay thin.

## Verification

- Unit: column derivation (roots + Unassigned), rollup incl. deep descendants and
  multi-assignment, membership; recategorize payload (replace-this-dimension-only,
  other dimensions preserved, Unassigned clears); VIEWER gating; selection callback;
  dimension-picker states.
- E2E: pick a dimension, see columns + cards; move a card via the move menu and assert the
  `change` payload categories; drag path exercised where stable.
- Architecture: `workspace-board` module/barrel/registry after `table`; no dnd dependency;
  move-menu accessibility pin.

## Rollback

The view registers additively; removing the descriptor + feature dir reverts to the
tri-view set with no other change.
