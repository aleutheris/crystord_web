# ADR-260067: Zoom-Progressive Node Level-of-Detail with Blender-Style Block

Status: Accepted
Date: 2026-07-18
Owners: Crystord App maintainers (info@aleutheris.com)

> Approval note: accepted under the project owner's batch delegation of 2026-07-17 covering
> the UI-exposure program's plan/decision approvals (recorded in `epic-index.md`).

## Context

`AtomNode` is sparse and its text is uniformly sized regardless of zoom — the worst of both:
no calm overview zoomed out, no information density zoomed in. The "Blender instinct": a node
editor reveals detail with zoom. EPIC-260066 shipped the layered node seam (`header · body ·
badges · handles`, `AtomNodeData.lod` reserved for exactly this); EPIC-260067 shipped the
deterministic label palette (`label-colors.ts`); EPIC-260069 fills the badges region with
compute status. React Flow exposes the viewport zoom via its store.

## Decision

1. **One epic, one mechanism, two states.** A single threshold (`LOD_THRESHOLD = 0.75` on
   the React Flow zoom) forks the **body region** between: **compact** (below) — a
   label-colored dot + truncated title, nothing else; **block** (at/above) — the dense
   Blender-style layout. Two states keep the mechanism testable; more gradations only if the
   block proves insufficient. The LOD/block split into two epics was rejected (both would
   edit `AtomNode` with a dependency between them).
2. **Dense block layout.** Header row: tiny truncated title + "ƒ" computed marker when
   `operation` is set. Meta row (monospace, tabular): the computed/content value
   (stringified, truncated) + the status text from the EPIC-260069 badge model. Dots row:
   round label dots colored by the shared `labelColorIndex` hash (same label = same color as
   the Classify chips) + square category-dimension dots colored by a dimension-key hash.
   Every dot carries its text in the tooltip/aria-label — never color alone (REQ-CR-260011).
3. **Seam discipline.** LOD renders entirely inside the **body** region; the badges region
   (EPIC-260069, absolute top-right) is untouched and composes over both states — an
   architecture test asserts the regions stay separate.
4. **Flow only.** The Network `CircleAtomNode` is untouched: its circle grammar is already
   calm at both zooms, and porting the region seam without a designed circle-block is
   speculative. The seam port remains the documented path if a Network LOD design
   materializes.

## Alternatives Considered

- **Split LOD mechanism and block design into two epics:** rejected — the block *is* the
  zoomed-in LOD state; splitting creates two epics editing one component in sequence.
- **Multiple zoom gradations (3+ LOD levels):** rejected for v1 — unfalsifiable added
  complexity; the two-state fork is testable and honest.
- **Port the region seam to `CircleAtomNode` now:** rejected — no designed circle block to
  render; a seam without a consumer is the pattern EPIC-260066 already declined.
- **Render values with a charting/sparkline dependency:** rejected — REQ-CR-260010; the
  block is DOM/monospace text.

## Consequences

- Positive: dense workspaces stay readable at both zoom extremes; classification and compute
  state become visible on the node itself; the seam pattern proves out with a second
  consumer (after badges).
- Negative: `AtomNode` body complexity grows (two render paths); zoom-reactive rendering
  re-renders nodes when crossing the threshold (bounded — a boolean, not continuous).
- Risks: dot rows could get long on heavily-classified atoms — capped with a "+N" overflow
  cell carrying the full list in its tooltip.

## Verification

- Unit: threshold fork (both states render the right structure); dot color determinism and
  overflow cap; tooltips/aria carry text for every dot; computed marker + meta row content;
  composition with a present `computeStatus` badge.
- Architecture: regions stay separate (badges markup unchanged); `LOD_THRESHOLD` literal
  pinned; `CircleAtomNode` untouched.
- Visual review against the "Blender feel" target (human step at epic review).

## Rollback

The fork lives in the body region of one component; reverting `AtomNode`'s body to the
previous title+labels rendering removes LOD with no contract change (`AtomNodeData.lod`
returns to reserved).
