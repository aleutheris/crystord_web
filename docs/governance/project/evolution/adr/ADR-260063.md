# ADR-260063: Classify Inspector — Chip Grammar, Deterministic Label Palette, and Category Round-Trip

Status: Accepted
Date: 2026-07-17
Owners: Crystord App maintainers (info@aleutheris.com)

> Approval note: accepted under the project owner's batch delegation of 2026-07-17 covering
> the UI-exposure program's plan/decision approvals (recorded in `epic-index.md`).

## Context

`DetailPanel` edits labels as one comma-separated text field — the weakest interaction in the
UI — and the schema-9.2.0 hierarchical category model (`AtomOutput.categories`,
`AtomInput.categories` with replace-all semantics, taxonomy read queries) is entirely unused on
the atom. EPIC-260066 shipped the inspector-tab registry and the shared `LabelChipEditor` /
`CategoryTree` widgets precisely for this leaf. Labels are informal/flat/fast; categories are
formal/hierarchical/structured — the two must read as different things (REQ-CR-260011 forbids
color-only distinction).

## Decision

1. **A Classify inspector tab** (feature `workspace-classify`, registered as `classify` after
   Details) owns label and category editing on the selected atom. `DetailPanel` drops its
   edit-mode labels field (the comma-box dies); creation mode switches to the shared
   `LabelChipEditor` (`change` requires labels at creation).
2. **Deterministic label palette.** An 8-slot desaturated chip palette joins `tokens.css`
   (light + dark) with a `labelColorIndex(label)` hash helper in `src/styles/label-colors.ts`
   (char-code sum mod 8) — same label, same color, everywhere (EPIC-260072 reuses it for node
   dots). Chip text is always rendered; color is never the sole signal.
3. **Chip grammar.** Labels = filled rounded pills tinted from the palette. Categories =
   outlined rectangular chips on neutral surface reading `Dimension ▸ Value` (dimension in
   secondary text). Distinct by shape + fill + prefix. The full ancestor path (client-derived
   from the dimension's values' `parentValueKeys` chain) rides in the chip tooltip, read-only.
4. **Pick-mode assignment.** "Assign category" opens the shared `CategoryTree` fed by new
   taxonomy read documents; selecting a value assigns its `valueKey` (most-specific value only —
   the backend derives the dimension). No taxonomy authoring here (EPIC-260068 owns it).
5. **Categories round-trip through the single mutation source.** `RETRIEVE_QUERY` selects
   `categories { dimensionKey valueKey }`; `Atom` gains optional `categories?` (optional keeps
   existing mocks valid — the established pattern); `useGraphData.updateAtom` maps
   `atom.categories` → `[{ valueKey }]` when present (schema replace-all; omitted → unchanged).
   New api-contract module `category-operations.ts` holds the taxonomy read documents + types.
6. **Immediate persistence.** Every chip action (add/remove label, assign/clear category)
   persists at once via `onUpdate` — classification is fast, no form save. VIEWER atoms render
   all chips read-only via `atomPermissions`.

## Alternatives Considered

- **Rework `DetailPanel` in place** instead of a new tab: rejected — details and classification
  are different jobs; the tab registry exists for exactly this, and DetailPanel stays small.
- **Free-hex or full-saturation label colors:** rejected — REQ-CR-260011 requires the restrained
  brand palette; a fixed 8-slot token set keeps dark-mode parity and the ESLint hex ban intact.
- **Form-save (batch) classification edits:** rejected — chips imply immediacy; batching
  reintroduces the save-button friction the epic exists to kill.
- **Fetching taxonomy display names per chip render:** rejected — one metadata load per tab
  mount (dimensions + relevant values) is enough; keys fall back where a name is missing.

## Consequences

- Positive: kills the comma-box; makes the category model visible on the atom; palette + grammar
  reused by EPIC-260068/072/075; categories round-trip unlocks Board (EPIC-260075).
- Negative: every chip action is a mutation + refetch round-trip (acceptable at current scale;
  the refetch path is the established one); two new visual grammars to keep consistent.
- Risks: replace-all category semantics mean a stale atom object could clobber a concurrent
  assignment — mitigated by the always-refetch-after-mutation data flow.

## Verification

- Unit: chip add/remove calls `updateAtom` with correctly built atoms; assignment/clear builds
  the replace-all categories array; hash determinism; VIEWER read-only; ancestor-path derivation.
- E2E: edit labels + assign a category on an atom, observe the `change` mutation and re-render.
- Architecture: `workspace-classify` in FEATURE_MODULES/barrels; tab registered; comma-box gone
  from DetailPanel edit mode; palette tokens present in both themes.

## Rollback

The tab registers additively; removing the descriptor + feature dir and restoring the
DetailPanel labels field reverts the surface. The `RETRIEVE_QUERY` categories selection is
additive and harmless to keep.
