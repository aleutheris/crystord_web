# ADR-260062: Table View — Registered Center View with Inline Edit and Shared Selection

Status: Accepted
Date: 2026-07-06
Owners: Crystord App maintainers (info@aleutheris.com)

## Context

EPIC-260066 delivered the four-region shell: a typed **view registry**, a shell-owned
`WorkspaceContext` (shared selection + working set), and a single `GraphData` mutation source
feeding every view. It also **demoted `SearchResultPanel`** out of the left rail, leaving **no
flat/tabular representation of the working set** until the Table view lands — the one interim
regression from the Foundation epic. EPIC-260071 is promoted to the lead leaf as the sole
regression-closer. The product is pitched to spreadsheet-minded users ("one spreadsheet row =
one Atom"), so a familiar grid is the most familiar on-ramp.

ADR-260032 set the dual-view (Network/Flow) delivery and validation baseline — shared
selection, centralized cross-view mutation reflection (ADR-260030 / REQ-OR-260010), feature-flag
rollout, and performance targets. Adding a third, non-graph view that also **edits cells**
extends that baseline to three views.

**Reality constraint (verified against the fetched `Atom`).** The atom exposes `labels`,
`bonds`, and `nuclearies { title, description, content, operation, constants }`. It does **not**
currently carry category facets, a compute/evaluation status, or `updatedAt` (`shellies` is
`{ uuid }` only). So the epic's originally-sketched column set (title · labels · category facets
· content · type · status, sorted by `updatedAt`) cannot be built as-is; the column scope must
be grounded in what the atom actually provides today.

## Decision

1. **Registration, not surgery.** Table registers as one `ViewDescriptor`
   (`{ id: 'table', label: 'Table', Component: TableView }`) in `view-registry.ts`, consuming the
   fixed `ViewProps` (`{ data, selectedAtomId, onSelectAtom, onCreateAtom, renderMode? }`). No new
   seam — this is the registration path ADR-260061 designed for. This **extends** ADR-260032's
   dual-view to a **tri-view** (Network / Flow / Table); it does not modify the graph views.
2. **Shared selection & working set (no new contract).** Table renders `data.atoms` as rows,
   reflects `selectedAtomId` as the selected row, and calls `onSelectAtom` on row click — opening
   the inspector, identical to node selection. Selection parity now spans three views (the
   ADR-260032 D1 parity assertion and `architecture.test.ts` extend from dual to tri-view).
3. **Inline edit through the single mutation source.** Editable cells persist via
   `data.updateAtom(uuid, atom)` — the same path `DetailPanel`/the inspector uses. Because all
   views render one `GraphData`, **cross-view mutation reflection is automatic and centralized**
   (ADR-260030 / REQ-OR-260010): an edit in Table updates the graph with no extra wiring. MVP
   editable cells: **title**, **content** (text), and **labels** (via the shared `LabelChipEditor`
   from EPIC-260066). Computed atoms (`operation != null`) render content **read-only** — Compute
   (EPIC-260069) owns computed values. Viewer-level atoms (effective access `VIEWER`) expose no
   editable cells, per ADR-260059.
4. **MVP column scope grounded in the atom:** title · labels · content · computed-indicator.
   **Category-facet and compute-status columns are explicitly deferred** to their owning epics
   (EPIC-260068 / EPIC-260069); when that data lands on the atom, Table gains columns
   **additively** — no rework.
5. **Sort: title A–Z for MVP.** `updatedAt` is not fetched (`shellies` is `{ uuid }` only), so
   "recently updated" sort is a deferred follow-up whose cost depends on backend support, **not
   verified here** (the schema-9.2.0 SDL is outside this repo): **if** the backend already exposes
   an atom timestamp, it is a client-only `retrieve`-query field addition (an ICR touch); **if
   not, it is a backend change**. To be confirmed when the enhancement is picked up. The sort
   mechanism is built **column-pluggable** so **user-selectable sort** (a stated future
   enhancement) drops in without restructuring.
6. **Not "home."** The node-graph remains the default view (Q1). Table registers after the graph
   views in display order — a first-class peer, not the landing view.

## Alternatives Considered

- **Build the full column set now** (category facets, status, `updatedAt` sort): rejected — that
  data isn't on the atom; it would force premature api-contract/category/compute work owned by
  EPIC-260068/069 and couple this epic to them.
- **A separate flat-list panel** (resurrect `SearchResultPanel`) instead of a registered view:
  rejected — puts a representation where navigation belongs (exactly what EPIC-260066 removed);
  the view registry is the sanctioned home for a working-set representation.
- **A dedicated table-edit mutation path:** rejected — forks the mutation source and breaks
  centralized cross-view reflection; reuse `updateAtom`.
- **Row virtualization in MVP:** deferred — follow the ADR-260032 degrade posture (reduced mode /
  gated large renders) rather than add a virtualization dependency now; revisit if row counts
  pressure the D2 timing targets.

## Consequences

- Positive: closes the sole EPIC-260066 interim regression; a familiar on-ramp; validates the
  shell's view-registry + shared-selection + inline-edit machinery with the safest feature;
  additive column growth; no new seam or dependency.
- Negative: a third view to keep in selection/mutation parity (tests + degrade behavior now
  tri-view); inline editing adds a new edit surface (table cells) that must respect access-level
  gating (ADR-260059).
- Risks: large working sets in a DOM table may pressure the ADR-260032 D2 timing (mitigate via
  the existing degrade thresholds / reduced mode, not new deps); the title-sort MVP diverges from
  the epic's `updatedAt` intent until the field is added.

## Verification

- Unit: `TableView` column rendering; row selection sync with `selectedAtomId`; title-sort
  ordering; inline edit calls `updateAtom` with the correct atom; computed atoms content
  read-only; VIEWER exposes no editable cells.
- Integration: cross-view mutation reflection (edit in Table → graph reflects); selection parity
  across Network / Flow / Table.
- E2E: switch to Table, edit a cell, see it persist and reflect in the graph; keyboard-only grid
  navigation.
- Architecture: `view-registry.ts` contains `'table'`; tri-view assertions updated.

## Rollback

Table registers additively; removing its `ViewDescriptor` entry (and the component) reverts to
the graph-only view set with no other change. Staged as small per-task commits; the epic can
return to Ideation and task commits revert without touching feature modules or the shell.
