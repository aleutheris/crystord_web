# Epic: EPIC-260075 — Board View: kanban bulk classify by dimension

- Epic ID: EPIC-260075
- Title: Board View — kanban bulk classify by dimension
- Persona/Actor: Users classifying many atoms at once.
- Value statement: For users organizing many atoms, deliver a kanban board (columns = a dimension's values, cards = atoms, drag to recategorize) so bulk classification is fast.
- Context: §3 designed a board view for bulk classify; it was unscheduled until now. It registers a *view* (Center region), so it could not fold into the Classify inspector tab (EPIC-260067).
- Problem statement: There is no fast surface for reclassifying many atoms; doing it one atom at a time in the inspector is slow.
- Expected outcome: A **Board** center view — columns are the values of one chosen category dimension, atoms are cards, and dragging a card between columns recategorizes it. Registered as a center view; shares the selection model.
- Success metric(s): Users pick a dimension and bulk-reclassify atoms by dragging cards between value columns.
- Non-goals: Per-atom classify (EPIC-260067); category authoring (EPIC-260068).
- Constraints: Depends on category dimensions/values existing; consistent with access gating (VIEWER atoms are not movable).
- Dependencies: EPIC-260066 (view registry); EPIC-260067 (categories on the atom + round-trip); EPIC-260068 (taxonomy reads in `category-operations.ts`).
- Target window: TBD. (Epic status lives only in `epic-index.md`.)
- Validation approach: Unit tests for column derivation + recategorize; E2E moving a card to a new value and confirming the category change.

## Ideation Bullets — Resolved (2026-07-17, plan review; approvals batch-delegated by the project owner this date)

- [x] **Dimension picker.** A select over `retrieveCategoryDimensions` (all accessible dimensions) in the board toolbar; no dimension chosen → prompt state. Choice is view-local state (not persisted — MVP).
- [x] **Columns + membership.** Columns = the chosen dimension's **root values** (fetched via `retrieveCategoryValues(dimensionKey)`, roots = empty `parentValueKeys`) plus a leading **Unassigned** column. An atom appears in a root column when its assignment for this dimension is that root **or any descendant of it** (rollup computed client-side from the dimension's full value list — the whole dimension is fetched anyway); atoms with no assignment in this dimension land in Unassigned. Cards show title + labels line; card click selects the atom (shared selection, inspector opens).
- [x] **Recategorize behavior + mutation path.** Native HTML5 drag-and-drop (no library — REQ-CR-260010 lean): drop on a value column assigns that root `valueKey`; drop on Unassigned clears this dimension's assignment; **other dimensions' assignments are preserved** (rebuild the categories array, replace only this dimension's entry) via the existing `updateAtom` categories round-trip from EPIC-260067. Access gating: VIEWER atoms render non-draggable with no move affordance (`atomPermissions.canEdit`). **Keyboard/a11y path:** every draggable card also carries a "Move to…" menu (column select) — the accessible equivalent and the deterministic E2E path (drag-only would fail the accessibility floor).
- [x] **Scope decision.** Board **ships in this round** — the project owner directed full implementation of the program (2026-07-17); it remains last in priority order as the most deferrable leaf.
- [x] **Full code + test coverage task** — included (T5).
