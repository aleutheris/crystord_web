# EPIC-260087: Contextual help for the inspector tab and the navigator lens

- Epic ID: EPIC-260087
- Title: Contextual help for the inspector tab and the navigator lens
- Persona/Actor: A workspace user who opens help while working in a specific inspector tab or
  left-rail lens.
- Value statement: For a user who is stuck on the tab or lens in front of them, open help on that
  section rather than on the center view's.
- Context: EPIC-260080 shipped in-app help that opens on the **center view**'s section, and
  deferred the tab and lens deliberately. This record exists because that epic's own text made
  spinning the question out a precondition of closing it.
- Problem statement: `activeView` is shell state (`WorkspaceShell.tsx`), so view-contextual open
  was nearly free. `activeTabId` (`Inspector.tsx:23`) and `activeLensId` (`LeftRail.tsx:25`) are
  **component-local** and absent from `WorkspaceContextValue`. Reaching them means either lifting
  them into a documented shell contract with three consumers, or adding a second entry point —
  and two doors to one panel is the over-provisioning ADR-260085 D1 rejected.
- Expected outcome: opening help from within a tab or lens lands on that surface's section.
- Non-goals: not a second help entry point; not a redesign of the help panel or its content model.
- Dependencies: EPIC-260080 / ADR-260085 (the panel and its contextual-open rule); ADR-260061
  (the slot registries and `WorkspaceContextValue`).
- Risks/assumptions: the cost is a shell-contract change, not help code — the panel already keys
  every section by registry id, so it can open on any of them today. Whether that contract change
  is worth it for a help affordance is the whole question, and EPIC-260080 declined to answer it
  speculatively.
- Target window: TBD.
- Validation approach: contextual open stays a pure function from state to section id, testable
  without React, as it is today.

## Ideation Bullets

- [ ] Is this worth a shell-contract change at all? The panel's table of contents already reaches
      every tab and lens section in one click, so the gain is saving that click.
- [ ] If yes: lift `activeTabId`/`activeLensId` into `WorkspaceContextValue` (three consumers, a
      documented contract), or pass the active id down to the help trigger some other way?
- [ ] Precedence when both could apply — the user is in the Compute tab of the Flow view. Does the
      inspector win over the center view, and on what rule?
