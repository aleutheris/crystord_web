# Epic: EPIC-260071 — Table View: spreadsheet-style peer to the graph

- Epic ID: EPIC-260071
- Title: Table View — spreadsheet-style center view
- Persona/Actor: Excel/Sheets-minded users; anyone scanning/editing many atoms at once.
- Value statement: For spreadsheet-minded users, deliver a familiar table/grid view so atoms can be scanned, sorted, and edited like rows — the most familiar on-ramp.
- Context: The user guide pitches Crystord as "one spreadsheet row = one Atom" and targets Excel/Sheets users, yet there is no spreadsheet-like view. The demoted left flat-list (`SearchResultPanel`) finds its proper home here.
- Problem statement: No tabular representation of the working set; the flat atom list was orphaned in the left rail (a representation living where navigation belongs).
- Expected outcome: A **Table** center view — MVP columns grounded in the current `Atom` shape: **title · labels · content · computed-indicator** (`nuclearies.operation != null`), **sorted by title A–Z** (user-selectable sort is a designed-for future enhancement). **Category-facet and compute-status columns are deferred** to their owning epics (EPIC-260068 / EPIC-260069) and compose in as new columns when that data lands on the atom. Inline-editable cells via the existing `updateAtom` mutation (so edits reflect across all views); registered as a center view sharing the selection/working-set model with Flow/Network.
- Success metric(s): Users view, sort, and inline-edit atoms in a grid; selection is shared with Flow/Network; Table is a first-class peer.
- Non-goals: Not "home" (the node-graph is, per Q1); the kanban board (EPIC-260075).
- Constraints: Q1 — Table is a strong first-class peer that supports the graph, not a competitor for "home."
- Dependencies: EPIC-260066 (view registry, shared selection/working-set contracts).
- Risks/assumptions: Inline-edit cells reuse the same mutation path as the inspector.
- Target window: TBD (Ideation).
- Validation approach: Unit tests for column rendering/sort + inline edit; E2E editing a cell and seeing it persist + reflected in the graph.

## Ideation Bullets — Resolved (2026-07-06, plan review)

- [x] **Column set + sort.** MVP columns are the fields that exist on the fetched `Atom`: title, labels, content, and a computed-indicator (`nuclearies.operation != null`). **Category facets and status are not on the atom yet** — deferred to EPIC-260068 (categories) / EPIC-260069 (compute status), added as columns when that data lands. **Sort: title A–Z** for MVP; `updatedAt` is not currently fetched (`shellies` is `{ uuid }` only), so "recently updated" sort is a follow-up whose cost depends on backend support (client-only fetch addition if schema 9.2.0 exposes an atom timestamp, else a backend change — confirm at pickup). **User-selectable sort is a designed-for future enhancement** (the sort mechanism is built column-pluggable).
- [x] **Inline-edit behavior + mutation path.** Cells edit via the existing `data.updateAtom(uuid, atom)` — the same path `DetailPanel` uses — so cross-view reflection is automatic (all views read one `GraphData`). MVP editable: title + content (text) and labels (via the shared `LabelChipEditor` from EPIC-260066). Computed atoms (`operation != null`) render content read-only (Compute owns it). Viewer-level atoms (ADR-260059) expose no editable cells.
- [x] **Shared selection + working set.** Row click → `onSelectAtom` (from `ViewProps`); selected row reflects `selectedAtomId`; opens the inspector, shared with Flow/Network. No new contract — `ViewProps` already carries selection.
- [x] **Coverage.** A dedicated full code + test coverage task (T6) is included, per `epic-process.md`.
