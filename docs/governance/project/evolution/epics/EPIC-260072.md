# Epic: EPIC-260072 — Node Visual Design: LOD & Blender-style blocks

- Epic ID: EPIC-260072
- Title: Node Visual Design — Level-of-Detail & Blender-style blocks
- Persona/Actor: Graph users navigating dense workspaces.
- Value statement: For graph users, deliver zoom-progressive node rendering with a dense, organized "Blender-feel" block so the graph stays readable when zoomed out and information-rich when zoomed in.
- Context: `AtomNode` is sparse *and* its type label is too big — the worst of both. The "Blender instinct" from §5: nodes should reveal detail by zoom, like a node editor.
- Problem statement: Nodes don't scale detail with zoom; there is no dense, legible block at high zoom and no calm overview at low zoom.
- Expected outcome: **Level-of-detail rendering** — zoomed out: a compact chip (dot + short title); zoomed in: a dense, organized block (tiny title; a metadata row of computed badge / value / status; label color-dots; category-dimension dots), small/tabular/monospace for values — "the Blender feel." Uses React Flow's zoom signal and the EPIC-260066 node-extension seam, composing cleanly with compute badges (EPIC-260069).
- Success metric(s): Nodes show progressively more detail as the user zooms in; the high-zoom block is dense and legible; low-zoom stays calm.
- Non-goals: The compute status badges themselves (supplied by EPIC-260069; this epic hosts them via the seam); node sockets/ports (visual density, not a node-wiring redesign).
- Constraints: Branding (REQ-CR-260011) — restrained palette, never color alone; render via the node-extension seam so badges and LOD layers don't collide.
- Dependencies: EPIC-260066 (node-extension seam — Flow `AtomNode`); EPIC-260067 (label color hash helper); EPIC-260069 (computeStatus data reaching node data).
- Target window: TBD. (Epic status lives only in `epic-index.md`.)
- Validation approach: Unit tests for zoom-threshold rendering states; visual review against the "Blender feel" target.

## Ideation Bullets — Resolved (2026-07-17, plan review; approvals batch-delegated by the project owner this date)

- [x] **Zoom thresholds.** One threshold, two states (`LOD_THRESHOLD = 0.75`, React Flow `useStore` zoom): below → **compact** (label-colored dot + truncated title, nothing else); at/above → **block** (dense layout below). Two states keep the mechanism testable and honest — more gradations only if the block proves insufficient.
- [x] **Granularity decision.** **One epic** (recommendation accepted): the Blender block *is* the zoomed-in LOD state; splitting would put two epics on `AtomNode` with a dependency between them.
- [x] **Dense block layout.** Header row: tiny title (truncate, 600 weight) + "ƒ" computed marker when `operation` is set. Meta row (monospace, tabular): computed value (stringified `content`, truncated) + status text from the EPIC-260069 badge model. Dots row: label dots (round, `label-colors.ts` hash — same label = same color as Classify chips) + category-dimension dots (square, dimension-key hash). Tooltips/aria-label carry the full text for every dot — never color alone (REQ-CR-260011).
- [x] **Composition with compute badges.** LOD renders entirely inside the **body** region; the EPIC-260069 badges region (absolute top-right) is untouched and composes over both LOD states — the seam does its job; an architecture test asserts the regions stay separate.
- [x] **Flow and/or Network.** **Flow `AtomNode` only** for this epic. Rationale: information density lives in Flow (the compute/analyst home per Q3); the Network circle grammar is already calm at both zooms, and porting the region seam to `CircleAtomNode` without a designed circle-block is speculative work. The seam port remains the documented path if a Network LOD design materializes (this epic then stops being "that consumer").
- [x] **Full code + test coverage task** — included (T5).
