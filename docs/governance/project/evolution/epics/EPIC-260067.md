# Epic: EPIC-260067 — Classify Inspector: label & category chip editors

- Epic ID: EPIC-260067
- Title: Classify Inspector — label & category chip editors on the atom
- Persona/Actor: Knowledge worker classifying atoms.
- Value statement: For users classifying atoms, deliver first-class label + category editing in the Inspector so classification is fast and structured — killing the comma-separated text box.
- Context: The right panel (`DetailPanel.tsx`) edits labels as a comma-separated string — the weakest spot in the UI — and categories are invisible on the atom.
- Problem statement: There is no real label/category editing surface; the v9.2 hierarchical category model is unused on the atom.
- Expected outcome: An Inspector **Classify** tab with (a) a **label chip editor** — autocomplete from `listLabels`, deterministic desaturated brand-palette color, text always shown; and (b) **category facet chips grouped by dimension** (e.g. `Region ▸ Belgium`), assignment by most-specific `valueKey` with derived ancestors, breadcrumb path read-only, editing opens the shared category tree in "pick" mode.
- Success metric(s): Users add/remove labels and assign/clear categories on an atom via chips; the comma-box is gone; labels and categories are visually distinct.
- Non-goals: The left-rail category navigator (EPIC-260068); bulk classify board (EPIC-260075); taxonomy authoring/permissions.
- Constraints: Branding (REQ-CR-260011) — desaturated palette, never color alone. Labels (informal/flat/fast) must look distinct from categories (formal/hierarchical/structured).
- Dependencies: EPIC-260066 (inspector-tab registry; shared label chip editor + permission-aware category tree).
- Risks/assumptions: Assumes the shared category tree's "pick" mode (from EPIC-260066) is reusable here.
- Target window: TBD. (Epic status lives only in `epic-index.md`.)
- Validation approach: Unit tests for chip add/remove + category assignment; E2E editing labels/categories on an atom and persisting.

## Ideation Bullets — Resolved (2026-07-17, plan review; approvals batch-delegated by the project owner this date)

- [x] **Label chip color hashing.** Deterministic hash (char-code sum mod 8) into a new 8-slot desaturated **chip palette** defined as CSS custom properties in `tokens.css` (light + dark) and exported as `C_LABEL_PALETTE` from `tokens.ts`; helper `labelColorIndex(label)` in `src/styles/label-colors.ts` (importable by ui-primitives and features — same label = same color everywhere; EPIC-260072 reuses it for node dots). Chip text always rendered — color is never the sole signal (REQ-CR-260011).
- [x] **Category facet-chip visual grammar.** Labels = filled rounded pills tinted from the hash palette. Categories = outlined rectangular chips on neutral surface with dimension-tagged text `Dimension ▸ Value` (dimension in secondary text color). Distinct by shape + fill + prefix — not by color alone.
- [x] **Breadcrumb path (read-only).** Chip shows `Dimension ▸ Value`; the full ancestor path (`Dim ▸ Ancestor ▸ … ▸ Value`, computed client-side from the dimension's values' `parentValueKeys` chain) rides in the chip's `title` tooltip. No inline path editing.
- [x] **"Pick" mode reuse.** An "Assign category" affordance opens the shared `CategoryTree` (ui-primitives/widgets) inside the tab, fed dimensions→values via `retrieveCategoryDimensions`/`retrieveCategoryValues`; selecting a value assigns its `valueKey` (dimension derived by backend; assignment is the most-specific value only). `canEditNode` is not wired here (no taxonomy authoring in this epic — EPIC-260068 owns it).
- [x] **Persistence path.** `RETRIEVE_QUERY` selection extended with `categories { dimensionKey valueKey }`; `Atom` type gains optional `categories?: { dimensionKey; valueKey }[]` (optional so mocks stay valid — established pattern); `useGraphData.updateAtom` round-trips `categories` (map to `[{ valueKey }]`) when present on the atom (schema replace-all semantics; omitted → unchanged). Classify actions persist **immediately per chip action** (add/remove label, assign/clear category) via `onUpdate` — classification is fast, no form save. New api-contract module `category-operations.ts` (taxonomy read documents + types). VIEWER atoms render chips read-only (via `atomPermissions`).
- [x] **Comma-box removal.** `DetailPanel` drops the labels field in edit mode (Classify owns labels); creation mode replaces the comma-box with the shared `LabelChipEditor` (`change` requires labels, so creation keeps a labels editor).
- [x] **Module shape.** New feature `workspace-classify` (ClassifyTab), registered as inspector tab `classify` after Details; added to `FEATURE_MODULES` + barrel contract in `architecture.test.ts`.
- [x] **Full code + test coverage task** — included (T7).
