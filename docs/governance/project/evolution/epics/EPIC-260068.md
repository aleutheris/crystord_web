# Epic: EPIC-260068 — Categories Navigator: left-rail faceted tree

- Epic ID: EPIC-260068
- Title: Categories Navigator — left-rail faceted category tree
- Persona/Actor: Knowledge worker browsing and scoping by structure.
- Value statement: For users exploring what data exists, deliver a left-rail Categories lens (faceted tree) so they can see how data is organized and scope the working set by category.
- Context: The brand promise is "the user can see what data exists." Hierarchical categories (dimensions→values) have no browse surface today.
- Problem statement: The v9.2 category model is invisible; categories can't be browsed or used as filters; a hierarchy can't live in a text box.
- Expected outcome: A left-rail **Categories** lens = expanding facet tree via `retrieveCategoryBrowse` (children + per-value `atomCount`). Faceted semantics map 1:1 to standard search: OR within a dimension, AND across dimensions, `includeDescendants` as one checkbox. Selecting values pushes chips to the top query bar. Inline edit affordances — ＋ add dimension/value, rename, delete (Q2).
- Success metric(s): Users expand categories with count badges and filter the working set; users author taxonomy inline without an admin surface.
- Non-goals: Per-atom category chips (EPIC-260067); the bulk-classify board (EPIC-260075); shipping taxonomy sharing UI (grants exist in schema — surfacing them is a future epic).
- Constraints: Q2 — no admin-only management surface; edit controls gate on the **real** per-node `accessLevel` from `Category*Output` (the taxonomy permission model is live in schema 9.2.0 — no speculative seam needed).
- Dependencies: EPIC-260066 (navigator registry; shared permission-aware category tree; filter builder). Shares the `category-operations.ts` api-contract module introduced by EPIC-260067.
- Target window: TBD. (Epic status lives only in `epic-index.md`.)
- Validation approach: Unit tests for facet selection semantics (OR/AND/includeDescendants); E2E browsing + filtering + inline taxonomy edit.

## Ideation Bullets — Resolved (2026-07-17, plan review; approvals batch-delegated by the project owner this date)

- [x] **Facet-tree UX.** `CategoriesNavigator` (new feature `workspace-categories`) renders the shared `CategoryTree`: top level = dimensions (`retrieveCategoryDimensions`), values lazy-load on expand via `retrieveCategoryBrowse(dimensionKey)` for roots and `retrieveCategoryBrowse(valueKey)` for subtrees; count badges from `CategoryChildCount.atomCount`. Atoms-under-node are **not** listed in the rail — navigators scope, views represent (count badges only).
- [x] **Inline taxonomy edit affordances.** Rail header ＋ adds a dimension; per-node affordances (via `CategoryTree`'s `canEditNode`/`onEditNode` + an inline editor): rename (`updateCategoryDimension`/`updateCategoryValue` displayName), add child value (`createCategoryValue`), delete (guarded — backend `CAT-*` errors surfaced verbatim through the mapper's generic path). **Drag-to-reparent deferred** (connect/disconnect ops exist; drag UX is disproportionate here — recorded as a follow-up, not a task).
- [x] **Permission seam (Q2).** `canEditNode` = the node's real `accessLevel` ∈ {OWNER, EDITOR} from `Category*Output.accessLevel` — the planned permission model already exists in 9.2.0, so gating is real data, not a seam. Taxonomy share/transfer UI is out of scope (mirrors EPIC-260074's model later).
- [x] **Chip push into the top query bar.** Facet state (`CategoryFacetFilter[]`, the ui-primitives `WorkspaceFilter` shape) is owned by `WorkspaceShell`. `NavigatorProps` extends **additively** with `filter?: WorkspaceFilter` and `onFilterChange?: (f: WorkspaceFilter) => void` (the contract EPIC-260066 deferred here). Value selection toggles that value in its dimension's facet entry (OR within dimension; AND across dimensions); one rail-level "Include subcategories" checkbox (default on) sets `includeDescendants` for new entries. Facet chips render in the shell header next to the SearchBar (removable, `Dimension ▸ Value` grammar from EPIC-260067); the shell appends the facet summary to the `QuerySummary` string. Facet changes trigger an immediate re-fetch combining the current submitted labels + facets: `GraphData.search` gains an optional `categories?` argument and `RETRIEVE_QUERY` a `$categories: [CategoryFilterInput!]` variable.
- [x] **Lens switcher.** This adds the second navigator, so the left rail gains the registry-driven lens switcher (Labels | Categories) mirroring the GraphViewTabs ARIA tab pattern.
- [x] **Full code + test coverage task** — included (T7).
