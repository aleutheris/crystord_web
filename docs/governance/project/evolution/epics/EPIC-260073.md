# Epic: EPIC-260073 — History Inspector tab: field-level change audit

- Epic ID: EPIC-260073
- Title: History Inspector tab — field-level change audit
- Persona/Actor: Any user (and auditors) needing to see how an atom changed.
- Value statement: For users needing transparency, deliver a per-atom change history so they can see who changed what, when, and with what remark.
- Context: The backend records field-level change history (`shellies.changes`) — a branding pillar ("Transparency") — that is completely invisible in the UI.
- Problem statement: There is no audit/history surface; users cannot see an atom's change trail.
- Expected outcome: An Inspector **History** tab listing field-level changes for the selected atom (who · when · field · remark), in reverse-chronological order.
- Success metric(s): Users open an atom and read its change log.
- Non-goals: Sharing/grants (EPIC-260074); account-level audit; live collaboration (excluded by REQ-CR-260010 — this is async audit, not real-time presence).
- Constraints: Async audit only (no RTC); read-only.
- Dependencies: EPIC-260066 (inspector-tab registry).
- Target window: TBD. (Epic status lives only in `epic-index.md`.)
- Validation approach: Unit tests for the change-log rendering; E2E viewing history after editing an atom.

## Ideation Bullets — Resolved (2026-07-17, plan review; approvals batch-delegated by the project owner this date)

- [x] **Change-log display + fields.** Schema confirmed: `shellies.changes(limit, offset): [ChangeEvent!]` with `timestamp`, `eventType`, `userId`, `remark`, `propertyChanges { field, oldValue, newValue, metrics { removedCount, addedCount, totalMembersAfter } }`. Each event renders: localized timestamp · eventType chip · remark (when present, italic) · per-property rows `field: old → new` (JSON stringified, truncated with full value in tooltip) · a compact metrics line for list-type fields. **`userId` is a raw id and the schema has no user-lookup query** — shown shortened (monospace, full id in tooltip); resolving display names is a recorded schema gap (future backend follow-up), not something this epic fakes.
- [x] **Ordering + pagination.** Server returns newest-first (documented) — rendered as-is. Page size 10; a "Show more" button appends the next offset; end-of-history inferred when a page returns fewer than `limit` (schema has no total count — page-size probing is the only option, documented). Fetched network-only on tab mount per atom (`retrieve(uuid)` selecting only `shellies { uuid changes(...) }` — the working-set query stays lean); a refresh affordance re-fetches page 0.
- [x] **Module shape.** New api-contract `history-operations.ts` (ATOM_CHANGES_QUERY + ChangeEvent types); new feature `workspace-history` (HistoryTab), registered as inspector tab `history`; strictly read-only.
- [x] **Full code + test coverage task** — included (T5).
