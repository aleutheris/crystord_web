# Epic: EPIC-260070 — Account & Settings: avatar menu & settings surface

- Epic ID: EPIC-260070
- Title: Account & Settings — top-right avatar menu and settings surface
- Persona/Actor: Any signed-in user managing their own account and environment.
- Value statement: For all users, deliver an account/settings surface so they can manage identity, workspace, and preferences — table stakes for real (non-demo) users.
- Context: The backend exposes a full account/identity layer (`setPassword`, `requestEmailChange`/`confirmEmailChange`, `authMethods`/`linkGoogle`/`unlinkAuthMethod`, workspace membership/roles) with no UI home. The top-right is three loose buttons (`ThemeToggle`, Account, Sign Out).
- Problem statement: No place to manage password/email/auth-methods/workspace/preferences; the Q3 compute-emphasis switch has no physical home.
- Expected outcome: A top-right **avatar dropdown** (consolidating today's `ThemeToggle`/Account/Sign-Out; **Sign Out pinned at the bottom**, separated) opening: **Account & identity** (the existing `AccountSettingsPanel`); **Workspaces** (list/create workspaces, manage members & roles); **Preferences** (theme + the Q3 emphasis switches).
- Success metric(s): Users reach account settings, workspace management, and preference toggles from one menu; Sign Out is at the bottom of the dropdown.
- Non-goals: Per-atom sharing (EPIC-260074); taxonomy permissions (future); workspace *switching* (no backend concept — see resolution).
- Constraints: The account-level complement to EPIC-260074's per-atom sharing; reuse the existing `AccountSettingsPanel`; preferences write the EPIC-260066 preferences contract.
- Dependencies: EPIC-260066 (**preferences contract only**). EPIC-260066 shipped no top-bar slot and no settings routes — this epic **reshapes the existing header directly** into the avatar dropdown; settings stay modal, not routed.
- Risks/assumptions: The avatar-dropdown slice is small/low-risk (reshapes existing controls, no new backend calls).
- Target window: TBD. (Epic status lives only in `epic-index.md`.)
- Validation approach: Unit tests for the dropdown + settings panes; E2E for menu navigation, preference toggling, and workspace management.

## Ideation Bullets — Resolved (2026-07-17, plan review; approvals batch-delegated by the project owner this date)

- [x] **Avatar dropdown contents and order.** Trigger = avatar button (username via `useAccountInfo` once loaded; generic glyph before). Menu (`role="menu"`, ArrowUp/Down + Home/End + Escape, click-outside close): identity header (username · email, non-interactive) → Theme (cycling item showing current mode, replaces `ThemeToggle`) → Account settings → Workspaces → Preferences → separator → **Sign Out pinned bottom**.
- [x] **Header reshape vs top-bar slot.** **Reshape directly** (the default stands): a top-bar slot has one consumer today; a registry for it would be speculative (REQ-CR-260010 lean). New `AccountMenu` lives in `ui-shell` (it composes feature barrels + shell prefs — shell chrome, like the header it replaces).
- [x] **Which panes ship.** All three in this epic, thin: **Account** = existing `AccountSettingsPanel` unchanged; **Preferences** = new shell-owned modal (`PreferencesPanel` in `ui-shell` — the preferences contract is shell state, features must not import ui-shell) with theme mode, `homeEmphasis`, `computeBadges` controls; **Workspaces** = new feature `workspace-admin` (modal): list my workspaces + create; per-workspace rename/description, members list, add member by username + role, change role, remove member, dissolve (two-step confirm). Caller's role derived by matching `me.username` in the member list; backend errors surfaced via the central mapper.
- [x] **Workspace switching vs management.** **Management only.** Schema 9.2.0 has no current-workspace/session-context concept — workspaces are sharing principals + membership, and `retrieve` takes no workspace argument. "Switching" has nothing to bind to; recorded as a backend-dependent future (would need a schema ICR).
- [x] **Preferences ↔ EPIC-260066 contract.** Preferences pane reads/writes `WorkspacePreferences` (`homeEmphasis`, `computeBadges` — consumed by EPIC-260069; rail-collapse prefs stay on the rails themselves). **No display-density setting** (not in the shipped contract; adding a key now would be speculative).
- [x] **Full code + test coverage task** — included (T6).
