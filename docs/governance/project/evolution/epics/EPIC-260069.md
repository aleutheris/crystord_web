# Epic: EPIC-260069 — Compute: formula builder & Flow visualization

- Epic ID: EPIC-260069
- Title: Compute — formula builder, computation transparency & Flow visualization
- Persona/Actor: Analyst-style user (heavy math / derived values); also any user with computed atoms.
- Value statement: For analyst-style users, deliver a formula builder plus computation transparency so derived values are easy to author and self-explaining — the product's headline differentiator (Q3).
- Context: The backend `operation` engine (SUM/MINUS/PRODUCT/DIVIDE/COLLECT, typing, dependency graph) exists; today the UI can't even edit the field. Highest-ceiling area, currently a void.
- Problem statement: No way to create or inspect computed atoms; the compute engine and its dependency graph are invisible.
- Expected outcome: An Inspector **Compute** tab = a formula builder — function picker from `discoverOperations`; argument slots (atom references picked by title, or constant keys; COLLECT's labels filter uses the shared label chip editor, label-only until backend adds category collect). Manual-vs-computed is a hard fork: once an atom has an `operation`, content flips to read-only "result" mode. An **"Explain this value"** section surfaces `evaluationStatus`/`errorCode`/`causes`/`cycleNodes` as plain language. Computation is visualized in the **Flow** view: status badges on nodes (via the EPIC-260066 node seam), cycles highlighted.
- Success metric(s): Users build a SUM/COLLECT atom without typing JSON; computed atoms show up-to-date/error status + an explanation; dependencies render in Flow.
- Non-goals: Charts/analytics (excluded by REQ-CR-260010); category-based COLLECT (backend not built — starts label-only).
- Constraints: Realized with the **current** stack (React Flow + DOM), **no charting library** (REQ-CR-260010); consumes the Q3 preference contract from EPIC-260066 (`homeEmphasis`, `computeBadges`); the toggle UI is EPIC-260070.
- Dependencies: EPIC-260066 (inspector-tab + view registries, node-extension seam, preferences contract).
- Risks/assumptions: Atom-reference picker is single-consumer and lives in this epic. `discoverOperations` returns name+description only (no arity metadata) — the builder keeps a client-side metadata table for the five built-ins.
- Target window: TBD. (Epic status lives only in `epic-index.md`.)
- Validation approach: Unit tests for the formula builder + "Explain this value" states; E2E creating a computed atom and seeing status + dependency edges.

## Ideation Bullets — Resolved (2026-07-17, plan review; approvals batch-delegated by the project owner this date)

- [x] **Formula-builder UX.** Function picker lists `discoverOperations` (name + description). Schema exposes **no arity/type metadata** (confirmed), so the builder carries a client-side metadata table for the built-ins — SUM (1+ args), MINUS (exactly 2), PRODUCT (2+), DIVIDE (exactly 2), COLLECT (special) — and falls back to a generic variadic args editor for unknown operation names. The canonical payload `{"name": "...", "args": [...]}` is parsed/serialized by pure helpers in api-contract (`operation-payload.ts`) — users never type JSON.
- [x] **Atom-reference picker.** Title-searchable picker over the current working set (never raw UUID entry); stores the UUID in `args`; existing UUID args render resolved titles (fallback: shortened UUID when the referenced atom is outside the working set). `InspectorTabProps` extends **additively** with `atoms?: Atom[]` (Inspector passes `workingSet.atoms`) so tabs can resolve references — documented in the ADR. Constant args reference keys from a key/value constants editor in the tab.
- [x] **COLLECT.** Argument = registered query name (client-side known registry: `atoms_with_labels`, with free-text fallback for future registrations); its `labels` constant edits via the shared `LabelChipEditor` — label-only until the backend adds category collect.
- [x] **Manual-vs-computed hard fork.** `operation` non-empty → Details tab content becomes read-only with a "Computed result" notice; the Compute tab owns the operation; "Convert to manual" clears the operation (inline two-step confirm) and re-enables content editing. Backend auto-manages `OP_DEPENDENCY` bonds (never submitted by the client — existing `stripSystemBonds` already guarantees this).
- [x] **"Explain this value" copy.** A section in the Compute tab (calm-competence tone): `success` → "Up to date — computed from N inputs."; `failed-origin` → plain-language cause (division by zero / missing dependency / type mismatch via `errorCode`); `failed-propagated` → "An input this value depends on failed" + causes resolved to atom titles; cycle (`AU-CYCLE-DETECTED`) → "These atoms form a loop" + cycle member titles; `skipped-optional` → "Skipped — an optional input is absent."
- [x] **Flow badges + cycle highlighting.** `RETRIEVE_QUERY` gains the evaluation fields (`errorCode evaluationStatus cycleNodes cycleEdges originNodeUuid affectedNodeUuid causes`, optional on `Atom`). A pure mapper (`compute-status.ts`, api-contract) folds them to a `computeStatus` badge model; GraphCanvas stamps it into `AtomNodeData.computeStatus` (the reserved badges region renders icon + text). Cycle members get error badges and cycle edges danger styling. Seam is Flow-only (matches this epic; no `CircleAtomNode` work).
- [x] **Charts decision.** Confirmed: v1 is graph/badges/table only — no charting library; any future charts require an ICR on REQ-CR-260010. Closed, no action.
- [x] **Emphasis preferences (Q3).** Per the T4 documented semantics: `computeBadges` `always` → badges on all computed atoms; `onDemand` → only on the selected atom (`ViewProps` gains optional `computeBadges?: 'always' | 'onDemand'`, shell passes the preference). `homeEmphasis` drives the **initial active view** (`compute` → Flow, `relationship` → Network, falling back to first enabled); the affected architecture assertion and Network-default E2E specs are updated in the same task (relationship-emphasis primed via localStorage where a Network-default scenario is kept).
- [x] **Full code + test coverage task** — included (T7).
