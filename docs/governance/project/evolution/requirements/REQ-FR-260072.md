## Statement

The system shall provide a **Categories** navigator lens in the left rail that browses the
taxonomy as a lazily-expanding tree (dimensions → values, per-value atom-count badges),
scopes the working set through facet selections — OR within a dimension, AND across
dimensions, with an include-subcategories toggle — surfaced as removable header chips, and
offers inline taxonomy authoring (add dimension/value, rename, delete) gated on each node's
real access level.

## Rationale

The hierarchical category model is invisible today: categories can be neither browsed nor
used as filters, and a hierarchy cannot live in a text box. A faceted tree delivers the brand
promise ("see what data exists") and lets users scope by structure — with taxonomy authoring
inline rather than behind an admin surface (Q2).

## Acceptance Criteria (behavioral)

- The left rail offers a lens switcher (Labels | Categories); the Categories lens lists
  dimensions and lazy-loads values on expand, each with an atom-count badge; no atoms are
  listed in the rail.
- Selecting values scopes the working set with OR within a dimension and AND across
  dimensions, re-fetching immediately in combination with the submitted label search.
- An "Include subcategories" checkbox (default on) controls descendant inclusion for new
  facet entries.
- Active facets render as removable `Dimension ▸ Value` chips beside the search bar, and the
  query summary reflects them.
- Add dimension (rail header), rename, add child value, and delete are available only on
  nodes whose access level is OWNER or EDITOR; backend `CAT-*` errors are surfaced verbatim.
