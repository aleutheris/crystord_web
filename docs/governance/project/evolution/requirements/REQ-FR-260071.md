## Statement

The system shall provide a **Classify** inspector tab through which the user edits the selected
atom's labels via a chip editor (autocomplete from the label listing; deterministic desaturated
per-label color with text always shown) and its category assignments via dimension-grouped
chips (`Dimension ▸ Value`) assigned from the shared category tree; every chip action shall
persist immediately through the shared atom-update mutation, and the comma-separated labels
text field shall no longer exist in the atom-details edit surface.

## Rationale

Classification is the product's fastest daily verb; a comma-separated text box cannot carry it,
and the hierarchical category model was invisible on the atom. Chips make both label and
category state visible, editable, and visually distinct (labels informal, categories formal).

## Acceptance Criteria (behavioral)

- The Classify tab lists the atom's labels as colored chips (same label → same color across the
  app; text always shown) with add (autocompleted) and remove affordances.
- Category assignments render as dimension-tagged chips; assigning opens the shared category
  tree in pick mode; selecting a value assigns its most-specific `valueKey`; a chip can be
  cleared.
- Every add/remove/assign/clear persists immediately via the shared update mutation and is
  reflected in all views without manual refresh.
- The full ancestor path of an assigned value is visible read-only (tooltip).
- Viewer-level atoms render all chips read-only (respects ADR-260059).
- The edit-mode comma-separated labels field is removed from the details surface; atom creation
  uses the shared chip editor.
