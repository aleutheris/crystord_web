## Statement

The system shall render Flow-view atom nodes with zoom-progressive detail: below the zoom
threshold, a compact representation (label-colored dot plus truncated title); at or above it,
a dense block presenting the title with a computed marker, a monospace meta row (value and
computation status), and capped rows of label and category-dimension dots — with every dot's
meaning available as text and the compute-status badge region composing unchanged over both
states.

## Rationale

Nodes that don't scale detail with zoom are noisy when zoomed out and uninformative when
zoomed in. Zoom-progressive rendering (the node-editor convention) keeps dense workspaces
readable at the overview and information-rich at close range, surfacing classification and
compute state where the work happens — the graph.

## Acceptance Criteria (behavioral)

- Below the threshold a node shows only a label-colored dot and a truncated title; at or
  above it, the dense block (title + ƒ marker when computed, monospace value/status meta
  row, label dots, category-dimension dots).
- Crossing the zoom threshold switches every node's state with no interaction required.
- Label dots use the shared deterministic palette (same label → same color everywhere);
  category dots are visually distinct from label dots (shape); dot rows cap with a "+N"
  overflow carrying the full list as text.
- Every dot exposes its label/dimension as text (tooltip and accessible name) — color is
  never the sole signal.
- The compute-status badge renders identically in both LOD states.
- The Network view's node rendering is unchanged.
