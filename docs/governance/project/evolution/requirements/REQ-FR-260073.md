## Statement

The system shall provide a **Compute** inspector tab through which the user authors an atom's
operation without typing JSON — choosing a function from the discovered operations, filling
argument slots with atom references picked by title or constant keys, and configuring COLLECT
via a registered query name plus a label-chip filter — shall render computed atoms' content
read-only with a convert-to-manual escape, shall explain the atom's evaluation state in plain
language, and shall visualize computation status in the Flow view via node badges and cycle
highlighting, honoring the compute-emphasis preferences.

## Rationale

The compute engine is the product's differentiator (Q3) yet is invisible: no way to author an
operation, no visibility into evaluation success or failure. A builder plus plain-language
explanation makes derived values authorable and self-explaining with the current stack — no
charting library (REQ-CR-260010).

## Acceptance Criteria (behavioral)

- The Compute tab lists discoverable operations; the five built-ins enforce their arity
  (SUM 1+, MINUS 2, PRODUCT 2+, DIVIDE 2, COLLECT 1 query + constants); unknown operations
  remain editable via a generic argument list.
- Argument slots accept atom references picked by title from the working set (stored as
  UUIDs, rendered as titles with a shortened-UUID fallback) or constant keys from the
  constants editor; COLLECT's labels constant edits via the shared label chip editor.
- Saving writes the canonical operation payload through the shared update mutation; the user
  never sees or types the JSON.
- A computed atom's content is read-only in the Details and Table surfaces; the Compute tab
  offers a confirmed "Convert to manual" that clears the operation and restores editing.
- "Explain this value" renders each evaluation state in plain language, naming failing
  inputs and cycle members by title where resolvable.
- Computed atoms in the Flow view carry a status badge (always, or only when selected, per
  the `computeBadges` preference); cycle members and cycle edges are visually flagged.
- The initial active view derives from `homeEmphasis` (`compute` → Flow, `relationship` →
  Network, falling back to the first enabled view).
- Viewer-level atoms expose no compute editing (respects ADR-260059).
