## Statement

The system shall provide a read-only **History** inspector tab listing the selected atom's
change events newest-first — timestamp, event type, author identifier, optional remark, and
per-property field transitions with list-change metrics — loaded on demand through a
dedicated lean query with incremental "Show more" pagination and a refresh affordance.

## Rationale

Field-level change history is a branding pillar ("Transparency") recorded by the backend but
invisible in the UI. A per-atom, on-demand audit trail surfaces who changed what, when, and
why (remarks) without burdening the working-set query.

## Acceptance Criteria (behavioral)

- Selecting an atom and opening History lists its change events newest-first with localized
  timestamp, event type, remark when present, and `field: old → new` rows (truncated, full
  values in tooltips); list-type fields show removed/added/total metrics.
- The author identifier is shown shortened with the full id accessible (no fabricated
  names); history is strictly read-only.
- Events load on demand per atom (the working-set query is unchanged); "Show more" appends
  older events and disappears when a page returns fewer than the page size; a refresh
  affordance reloads from the start.
- Empty history and load errors render distinct, announced states.
